# 静态断言内容锚指南（R-11 · E21——4-3a/E13 两轮实证的模式成文）

## 问题：行号锚的脆弱性

`assert.equal(hits[0].line, 625)` 形态的静态断言锚定**源码行号**——任何前置插入/删除
（含与本断言无关的他批改动）都会使行号漂移，断言在语义未变时假红。4-3a 两轮 CI/本地
±3 漂移与 E13 brainDir 修正均为此形态。

## 内容锚模式（三条硬规则）

1. **恰此一处**：先断言命中计数（如平衡括号扫描 `hits.length === 1`）——唯一性是内容
   锚的前提，多命中=锚点选错。
2. **内容验证**：断言命中行的**语义内容**（函数签名/不变式文本/调用形态），不断言行号。
   `assert.ok(src.includes('sanitizeUntrusted(String(opts.linkContext).slice(0, 800))'))`。
3. **等价性测试背书**：内容锚替换行号锚时，附新旧断言等价的对照测试（③④等价性测试
   形态——证明"锚换了，被锚的语义约束一条没少"）。

## 审查清单（新静态断言入库前）

- [ ] 断言的是语义约束还是物理位置？（位置=候选内容锚）
- [ ] 唯一性有没有显式断言？
- [ ] 命中内容的断言能否独立读懂（不回源码）？
- [ ] 行号→内容锚迁移是否附等价性背书？

## 存量审查（E21 实测）

grep 形态 `\.line,?\s*\d+` 扫测试面——4-3a 已内容锚化（E13）；其余命中=数字字面量
断言（非行号锚）或已内容锚形态；**无未处置行号锚存量**（2026-10-17 实测口径）。
